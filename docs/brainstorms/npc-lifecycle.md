# NPC Lifecycle — программа минимум

Три фазы оживления НПС. Каждая самодостаточна — после любой фазы игра уже играбельна.

---

## Фаза 1 — Локации, расписание, перемещение (0 LLM)

### Мир как граф локаций

Весь мир — плоский граф. Каждый узел — **локация** (Location). Каждое ребро — расстояние в метрах. Одна сущность, одна механика перемещения для любого масштаба.

```
[tavern]──200m──[market]──300m──[gate]──40km──[highfield_gate]──500m──[highfield_market]
```

Локации различаются масштабом, но не типом:
- Комната в таверне, кузница, рыночная площадь — узлы
- Городские ворота — узел (граница "внутри/снаружи")
- Дорога между городами — одно ребро с весом 40 км (пока автор не добавил точку интереса, разбив ребро)

Нет иерархии Region > Settlement > Location. Регион и поселение — **теги** на локации (для погоды, экономики, привязки НПС), не уровни вложенности.

### Перемещение

`go <location_id>` — только в соседний узел (есть прямое ребро). Хочешь далеко — шагай по цепочке.

```
> go market
Ты идёшь на рыночную площадь. (3 мин)

> go royal_castle
Отсюда нельзя попасть в Королевский замок. Доступные пути: tavern, gate, smithy

> go gate
Ты идёшь к городским воротам. (5 мин)

> go highfield_road
Ты выходишь на дорогу в Хайфилд. (8 часов пути)
```

Время = расстояние / скорость. Скорость модифицируется террейном, погодой, высотой (формулы уже есть в `rules/geography.py`). Мгновенного перемещения нет — **каждое действие стоит времени**.

Путешествие как процесс с прерываниями (случайные встречи, смена погоды, ночёвка) — на будущее, но архитектурно закладываем.

### Геймплей

Игрок изучает мир, запоминает маршруты, спрашивает НПС "как пройти к замку". В будущем — навык картографии, купленные карты, fast travel.

### Расписание НПС (computed, не state)

НПС не хранят текущую локацию как стейт. Расписание — **функция от времени**:

```python
def current_location(self, hour: int) -> str:
    if self.location_override:
        return self.location_override
    for entry in self.schedule:
        if hour_in_range(hour, entry.start_hour, entry.end_hour):
            return entry.location_id
    return self.home_location
```

`on_tick` каждые 6 секунд **не нужен**. `wait 10min` просто двигает часы, без пересчёта. Когда игрок делает `look` — вычисляем кто где на этот момент.

**`location_override`** — единственный стейт. Ставится когда НПС выбит из рутины:
- В бою (залочен в точке боя)
- В разговоре с игроком (не телепортируется)
- Ручное перемещение мастером
- Фаза 3: LLM решил что НПС ушёл в ополчение

Снимается автоматически (бой/разговор кончился) или вручную.

### `look` фильтрует по локации

Показывает только тех НПС, чей `current_location(hour)` совпадает с локацией игрока:

- Рынок в 10 утра → видишь торговца и фермера
- Рынок в 22:00 → пусто, все в таверне или дома
- Кузница ночью → "Грунд спит" (можешь разбудить)

### Флейвор-строки

При `look` рядом с НПС: "Грунд работает у наковальни" / "Грунд сидит с кружкой эля". Словарь `{(role, activity) → flavor_text}`, без LLM.

### Где живёт граф

Граф — структура мира, не процесс. Ему не нужен `tick`, он не генерирует события. Живёт в **core** рядом с World. Слои используют его данные:
- Geography даёт террейн/погоду для расчёта скорости
- Settlements тегируют узлы экономикой
- Entities знают кто на каком узле

### YAML

```yaml
# locations.yaml
silverport_tavern:
  name: "Таверна «Солёный якорь»"
  settlement: silverport_city
  region: silverport
  neighbors:
    - target: silverport_market
      distance: 200    # метры
    - target: silverport_docks
      distance: 150

silverport_gate:
  name: "Городские ворота"
  settlement: silverport_city
  region: silverport
  neighbors:
    - target: silverport_market
      distance: 300
    - target: silverport_highfield_road
      distance: 500

silverport_highfield_road:
  name: "Дорога в Хайфилд"
  region: silverport       # террейн/погода берутся из региона
  neighbors:
    - target: silverport_gate
      distance: 500
    - target: highfield_gate
      distance: 40000      # 40 км
```

**Итог:** мир чувствуется живым. Город пустеет ночью, утром оживает. Перемещение занимает время. Ноль LLM-вызовов.

## Фаза 2 — Память и осведомлённость (LLM при диалоге)

Когда игрок **заговаривает** с НПС — тот знает контекст.

### Event digest

Перед LLM-вызовом собираем что произошло в регионе с последнего разговора. Уже есть через `get_perceived_log`, нужно скармливать в промпт.

### conversation_summary

После диалога LLM генерирует 1-2 строки summary → сохраняется на НПС. При следующем разговоре — в контексте. Поле уже есть, нужно подключить.

### RuleBrain-заглушка для диалога

Без LLM — canned response по роли и activity: "Покупать будешь?" (merchant+working), "Проваливай, я занят" (guard+working), "Zzz..." (sleeping).

**Итог:** НПС помнят, что было. Без LLM — минимальные но осмысленные реплики.

## Фаза 3 — Автономные тики ключевых НПС (L2)

### Тиры НПС

```python
class NpcTier(Enum):
    BACKGROUND = "background"   # L1: только расписание
    IMPORTANT  = "important"    # L2: реагирует на события
    KEY        = "key"          # L2+: периодические автономные тики
```

### Триггерный тик (IMPORTANT + KEY)

Мировое событие затрагивает НПС → один дешёвый LLM-вызов:

```
Ты кузнец Грунд. Характер: грубый, честный.
Произошло: объявлена война с орками.
Ответь JSON: {"schedule_change": "...", "mood": "...", "new_goal": "..."}
```

### Периодический тик (только KEY)

Раз в N игровых дней — тот же формат. Антагонист строит планы, компаньон развивается.

### Graceful degradation

Без LLM триггерные тики не срабатывают, НПС остаются на фазе 1. Игра работает, мир просто более статичный.

**Итог:** мир живёт без игрока. Вернулся через 3 месяца — кузнец ушёл в ополчение, торговец сбежал.
