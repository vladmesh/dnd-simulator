# Round System: раунд как основа игры

Обсуждение 2026-03-21.

> **Актуализация 2026-07-04:** модель времени пересмотрена в [simulation-core.md](simulation-core.md) — «один раунд на весь мир» стал «одной временной линией»: 6с-раунд как семантическая истина, намерения с wake-точками, сцены. Этот док — историческая база.

## Инверсия причинности

Сейчас: `world.advance_time(6s)` → тикает EntitiesLayer → NPC делают ход.
Правильно наоборот: **раунд первичен, время — следствие**.

Раунд — атомарная единица игры. Все активные сущности сделали ход → мир двигается
на 6 секунд. Не "мир сдвинулся и триггернулся уровень с сущностями", а "произошёл
ход и как результат мир двинулся".

## Round — оркестратор, не слой

Round не слой в стеке. Слои — данные и реакции (география, политика, поселения,
сущности). Round — механика игры, цикл принятия решений. Живёт над слоями,
отдельный класс рядом с World.

World — контейнер данных и слоёв. Round — оркестратор поведения.

```
Round (оркестратор)
  │
  ├─ collect active entities from EntitiesLayer
  ├─ for each: brain.choose_action() в цикле (несколько действий за ход)
  ├─ execute actions (emit events)
  ├─ world.advance_time(1 round)
  │     ├─ geography.tick()
  │     ├─ politics.tick()
  │     ├─ settlements.tick()
  │     └─ entities.tick() ← Level 2: триггеры, батч-LLM, обновление трейтов
  └─ check reactivation triggers
```

## Активные vs неактивные сущности

Два режима существования:

**Активные** — участвуют в раундах, brain дёргается каждый ход. Это уровень 3
сознания (полностью сознательный). Игроки, NPC в сцене, пробуждённые LLM-агенты.

**Неактивные** — квантовое облако. Живут по расписанию, но не тикают.
Материализуются при наблюдении (попадают в awareness активных) или взаимодействии.

### Триггеры активации (неактивный → активный)

- **Взаимодействие**: активный entity обращается к неактивному → тот активируется
- **Событие мира**: война пришла в регион → ключевые NPC активируются
- **Мастер**: ручное `activate(entity_id)`
- **Пробуждение**: мастер ставит `active = True` на LLM NPC → автономный агент

### Триггеры деактивации (активный → неактивный)

- **Wait**: "ждать 10 минут" = выход из активных с таймером
- **Конец сцены**: NPC закончил разговор/бой, нет причин оставаться активным
- **Мастер**: ручное `deactivate(entity_id)`

### Наблюдение без активации

Игрок пришёл на рынок → неактивные NPC появляются в awareness ("тут Мария"),
но не активируются. Активация только при прямом взаимодействии (say, attack).

## Три уровня сознания → Round + tick

Из [game-loop-and-master.md](game-loop-and-master.md) и [npc-lifecycle.md](npc-lifecycle.md):

**Уровень 3 (сознательный)** = `active: true`. Round крутит каждый раунд.

**Уровень 2 (полусознательный)** = `EntitiesLayer.tick()`. Событие мира (война,
катастрофа) → проверка триггеров → дешёвый батч-LLM → обновление трейтов/расписаний.
Не раунд, а фоновый процесс.

**Уровень 1 (спящий)** = расписание, формулы. Не тикает вообще.

## Два режима раунда

**Свободный (free)** — действия разрешаются по мере поступления, порядок не важен.
Все активные ходят "одновременно". Для мультиплеера — барьер: ждём всех.

**Turn-based** — включается по триггеру (бой, команда мастера, ловушка, скрытность).
Инициатива, строгий порядок. Команды могут быть как боевые так и мирные — зависит
от контекста, не от режима. Аналог turn-based mode из BG3.

Бой — частный случай turn-based, не отдельная система.

## Несколько действий за ход

D&D 5e ход — не одно действие, а бюджет: Action + Bonus Action + Movement +
Free Interaction. После каждого действия мир мог измениться.

Brain ведёт диалог в рамках хода:

```
← awareness (начало хода)
→ action: move toward goblin1
← action_result + updated awareness
→ action: attack goblin1
← action_result + updated awareness
→ action: bonus_action healing_word ally1
← action_result
→ end_turn
```

`choose_action()` вызывается в цикле, пока brain не вернёт `end_turn`.
Каждый вызов получает обновлённый awareness.

## Fast-forward (все неактивны)

Когда все сущности неактивны (все ждут / путешествуют): не итерируем по 6 секунд,
а прыгаем до ближайшего тика слоя. Слои сами знают когда у них следующий тик.

Прыгнули → тик → если прилетело событие, затрагивающее спящего → активируем →
выход из fast-forward, нормальные раунды.

Для игроков в этот момент "экран загрузки" / "идёт путешествие".

Тонкость: если один игрок путешествует 10 часов, а другие в бою — путешественник
не доберётся пока бой не кончится (раунды по 6 секунд). Это ок.

## Перемещение между локациями

Простая модель: персонаж на время путешествия пропадает из мира (техническая
локация или `location_id = None`). Мир на него не влияет.

Случайные встречи привязываются к таймеру: "на третий час пути активируется
в локации X". Остальное время — не существует на карте.

Сложная модель (каждая локация имеет размер, пересечения в пути) — возможна,
но огромный скоуп ради edge cases. Не сейчас.

## Транспорт: WebSocket

Основной протокол — WebSocket. REST остаётся для stateless запросов
(sessions, world templates).

CLI — отладочный инструмент, тонкий WS-клиент. Не проектируем под CLI.

### Протокол

```
← {"type": "awareness", "mode": "free|turn_based", "data": {...}, "events": [...]}
→ {"type": "action", "name": "attack", "params": {"target_id": "goblin1"}}
← {"type": "action_result", "success": true, "events": [...]}
→ {"type": "end_turn"}
← {"type": "round_end"}
... ждём пока все походят ...
← {"type": "awareness", ...}  // новый раунд
```

Queries (look, status, map) — не тратят ход:

```
→ {"type": "query", "name": "look"}
← {"type": "query_result", "name": "look", "data": {...}}
```

### Awareness — уже JSON

Awareness — датакласс (`PeacefulAwareness`, `CombatAwareness`), сериализуется
через `dataclasses.asdict()`. Транспорт отдаёт как есть. Форматирование —
забота клиента, не сервера.

## Что это открывает

- **Мультиплеер**: игрок = обычный active entity с PlayerBrain. Сколько угодно.
- **Персонажи мастера**: DM "вселяется" в NPC, играет за него.
- **Пробуждение**: `active = True` + `LlmBrain` = автономный агент. Мастер
  переключает active/inactive и LlmBrain/RuleBrain как LOD-систему.
- **Один Brain**: PlayerBrain один (не CLI/API варианты). Читает action
  из очереди, куда WebSocket handler кладёт.
