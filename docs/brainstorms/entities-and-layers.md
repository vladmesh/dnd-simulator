# Сущности и слои

Обсуждение 2026-03-20.

## Слои = уровень абстракции

Слои существуют потому что нет ресурсов пересчитывать всё каждую секунду.
Организующий принцип: **частота обновления + близость к игроку**.

```
Geography    — физический мир, тикает каждый вызов
Politics     — государства, тикает раз в 30 дней
Settlements  — поселения, тикает раз в 30 дней
Entities     — все существа (игрок, NPC, монстры), частота зависит от активации
```

## Entities — единый слой существ

Все трекаемые существа живут на одном слое: игрок, NPC, именованные монстры.
Текущий NpcLayer расширяется до EntitiesLayer (инкрементально, не переписываем).

Игрок — тоже сущность на этом слое. GameSession хранит только session_id +
указатель на игрока.

## Два вида существ

**Трекаемые** — на слое Entities. Кузнец Гаррик, Главзлодей, король, компаньон.
Хранятся индивидуально, у каждого свой бэкграунд и характеристики.

**Статистические** — нигде не хранятся. Параметр региона или поселения:
"в лесу волки CR 1/2, плотность средняя", "в деревне 200 крестьян".
Конкретный волк или крестьянин генерируется на лету когда нужен.

## Уровни сознания (заменяет бинарную active/idle модель)

Развёрнуто в [game-loop-and-master.md](game-loop-and-master.md). Кратко:

```
Уровень 1: Спящий     — формулы, расписание, без LLM
Уровень 2: Полусознат. — дешёвый LLM-вызов при важном событии, батчами
Уровень 3: Сознательный — полный контекст, tool use, каждый раунд (рядом с игроком)
```

НПС всегда "живой", вопрос только в частоте и глубине обновления.
Трейты и расписания реально меняются через LLM на уровне 2,
а не только при прямом взаимодействии с игроком.

## Генерация статистических существ

Три механики спавна:

| Механика | Триггер | Кто решает | Пример |
|----------|---------|-----------|--------|
| По запросу | Игрок хочет взаимодействовать | Мастер (LLM) | Крестьянин на рынке |
| Random encounter | Перемещение / ожидание в опасной зоне | Бросок кубика | Волки в лесу |
| Scripted encounter | Конкретный триггер из YAML | Контент | Торговец на дороге |

Random encounter — первый кандидат на реализацию. Чистые функции в rules/:
```
encounter_chance(region_danger, terrain, time_of_day, travel_hours) → bool
spawn_encounter(terrain, danger_level, rng) → list[Creature]
```

Сгенерированные существа живут только пока актуальны. Бой кончился → исчезли.
На слой Entities не попадают.

## Форсированный тик снизу вверх

Нижние слои могут вызвать внеочередной тик верхних. Убил короля →
Event(LEADER_KILLED) → политический слой пересчитывается немедленно,
не ждёт 30 дней.

Механизм: расширить handle_event() так, чтобы он мог запустить полный
пересчёт слоя, а не только точечную реакцию.

## Связь именованных сущностей с верхними слоями

Король напрямую связан со слоем Politics — его смерть / свержение
триггерит политические события. Старейшина деревни связан с Settlements.
Это будущая механика — пока фиксируем как направление.
