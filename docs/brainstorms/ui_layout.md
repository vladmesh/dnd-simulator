# UI Layout & Action Grouping Brainstorm

## 1. Архитектура экрана (Layout)
Проблема текущего интерфейса состоит в том, что лог событий занимает центральное место на экране и не имеет ограничения по высоте. Когда сообщений в логе становится много, весь интерфейс растягивается вниз, что заставляет игрока скроллить всю страницу целиком, теряя из виду карту боя, инвентарь или список ближайших объектов.

### Предлагаемое решение:
*   **Глобально фиксированная высота (`100vh`)**: Основной контейнер игрового окна должен занимать всю доступную высоту окна браузера без глобального скролла.
*   **Независимый скролл-контейнер для лога**: Блок с логом должен получить свойство `overflow-y: auto`, что позволит прокручивать историю событий внутри ограниченного прямоугольника, оставляя остальные элементы интерфейса (карта, кнопки действий) на статичных местах.
*   **Смена визуальных приоритетов**: 
    *   Центральную часть экрана стоит отдать под карту, список объектов или графическое представление инвентаря/сцены.
    *   Лог может стать либо вертикальной панелью слева/справа (как окно чата в MMO), либо занять горизонтальную полосу определенной высоты (например снизу над панелью действий).
*   **Табы (Вкладки) для виджетов стайтуса (правой панели)**: Чтобы сэкономить вертикальное место, вместо длинного списка (Инвентарь + Торговля + Враги) следует использовать вкладки. В бою должна доминировать вкладка карты и информация о врагах, а вне боя — торговля/исследование и инвентарь.

## 2. Форматирование лога и читаемость
Текущий лог выдает стену монотонного текста, в котором тяжело визуально ориентироваться. Особенно это касается повторяющихся однотипных действий вроде многократного движения на 5 футов по прямой.

### Предлагаемые решения:
*   **Агрегация (Rollups / Сворачивание однотипных действий)**: Если сущность совершает несколько одинаковых действий подряд (например, 5 шагов/движений), в лог должна падать только агрегированная запись (например, "▼ Волк переместился (25 ft)"), которую при необходимости можно развернуть кликом через `<details>`.
*   **Группировка по ходам и раундам**: В бою визуально отделять действия блоков друг от друга. Возле начала хода показывать заголовок или плашку с фоном (например: **Ход: Гоблин 1**), внутри которой перечислять действия сущности за этот ход в виде списка.
*   **Цветовое кодирование и иконки**: Знаковая визуализация сильно облегчит чтение: серый цвет и иконка стрелочки для шага, красный с иконкой меча для урона, синий с зельем для лечения/лута. Жирное выделение критических чисел (криты, количества урона).
*   **Фильтрация вкладок лога**: Добавить над логом вкладки-фильтры (Все / Только бой / Диалоги и лут) или чекбокс-настройки вроде "Скрыть перемещения".

## 3. Организация действий (Skills / Actions Bar)
В перспективе, количество доступных действий (атаки, магические заклинания, артефакты) вырастет до десятков. Делать сложный drag-and-drop интерфейс для свободной расстановки иконок (как в WoW или Baldur's Gate 3) — трудозатратно для веб-разработки на раннем этапе и требует сложного сохранения UI-состояния (стэйта перса).

### Выбранный гибридный подход панели (JRPG / Solasta):
Комбинация Core-панели и всплывающих ящиков-категорий (Drawers / Folders) в сочетании с Auto-Сортировкой под капотом:

1.  **Core-панель (Быстрые кнопки)**: Статично закрепленная горизонтальная панель внизу по центру, на которой всегда выведены основные действия сущности:
    *   Атака (основным выбранным оружием/кантрипом)
    *   Рывок
    *   Отход / Уклонение
    *   Конец хода
2.  **Меню категорий (Книги/Папки)**: Рядом с быстрыми действиями располагаются крупные кнопки-категории ("Книга заклинаний", "Инвентарь/Зелья", "Классовые умения").
3.  **Всплывающее меню (Pop-ups / Drawers)**: При клике на "Книгу заклинаний" над панелью плавно всплывает окно/шторка со списком всех кастов, отсортированных по уровням ячеек. Выбор скилла происходит в два клика (Клик по книге -> клик по нужной кнопке).
4.  **Визуальное разделение типов по правилам D&D**: Автоматическая визуализация доступности скиллов: "Стандартное действие" (Action), "Бонусное действие" (Bonus Action), "Реакция" (Reaction). Если в этот ход уже было потрачено бонусное действие, соответствующие умения в меню становятся серыми (disabled).

**Итог по управлению действиями:**
Такой гибрид избавит от необходимости писать сложную логику управления кастомными панелями с drag-and-drop, сохранит UI максимально чистым (без миллиона кнопок-микроквадратиков) и позволит свободно масштабировать количество скиллов для любых классов персонажей.
