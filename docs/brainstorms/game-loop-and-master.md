# Главный цикл, Мастер и живой мир

Обсуждение 2026-03-20.

> **Актуализация 2026-07-04:** активация, пробуждения и роль мастера пересмотрены в [simulation-core.md](simulation-core.md) — явное назначение активных, парные триггеры `{on, until}`, гашение, интерлюдии. Этот док — историческая база.

## Одна петля — всегда

Нет двух режимов (свободный / пошаговый). Один цикл:

```python
while True:
    for creature in active_creatures:
        creature.take_turn(world)
```

- `active_creatures = [player]` → игра бесконечно опрашивает игрока
- `active_creatures = [npc1, npc2, player]` → НПС ходят, потом игрок
- Никакой развилки в коде

Активация/деактивация НПС — механическая (area-based), не решение LLM.

## Мастер — интерфейс игрока к миру

Игрок **никогда не видит сырых данных**. Не парсит команды, не видит лог событий
напрямую. Пишет свободный текст, общается с Мастером.

Мастер — не существо и не слой. Это **стратегия ввода-вывода** для игрока,
аналог LLM у НПС. Инжектится в PlayerCharacter, может быть None (masterless mode).

```python
class PlayerCharacter:
    master: Master | None

    def take_turn(self, world):
        if self.master:
            self.master.handle_player_turn(self, world)
        else:
            self._raw_take_turn(world)  # masterless: прямые команды
```

### Masterless mode

Текущий PlayerCharacter.take_turn() — прямые команды (look, attack, say, idle).
Остаётся как:
- Режим разработки/отладки (не тратить токены)
- Fallback без API-ключа
- Классическая текстовка

### Ручки мастера (tool use)

Мастер получает свободный текст игрока и дёргает ручки мира:

```
move_player(area_id)           — переместить игрока
advance_time(seconds)          — продвинуть время (один чанк)
activate_entity(entity_id)     — ввести НПС в сцену
deactivate_entity(entity_id)   — убрать НПС из сцены
query_world(layer, question)   — спросить мир о чём-то
emit_event(event)              — бросить событие в мир (say, attack, ...)
roll_check(entity_id, ...)     — бросок кубика
narrate(text)                  — сказать игроку
ask_player(prompt)             — спросить игрока (уточнение)
```

### Пример потока

```
Игрок: "бью гоблина мечом"
  → Мастер (LLM)
    → emit_event(ENTITY_ATTACK, attacker=player, target=goblin, weapon=longsword)
    ← AttackResult(hit=True, damage=7)
    ← perceive_event → "Ты замахиваешься мечом..."
    → narrate("Ты наносишь удар мечом по гоблину. Лезвие рассекает...")
  ← Игрок видит нарратив
```

## Время

### Раундовое время

Каждое действие имеет неявную длительность. После полного раунда (все сходили)
game loop двигает время:

```python
# Бой: 6 секунд на раунд
# Разговор: ~минута
# Мастер решает дельту исходя из контекста
world.advance_time(round_delta)
```

### Нарративное время (длительные действия)

Игрок: "иду в соседний город" или "жду до утра".

Мастер внутри своего хода крутит время **чанками с проверками**:

```python
def handle_travel(player, destination, world):
    total_hours = calc_travel_time(player.area, destination)
    chunk = TimeDelta.from_minutes(30)

    for _ in range(total_hours * 2):  # чанки по 30 мин
        world.advance_time(chunk)
        events = collect_important_events()

        if random_encounter():
            narrate("На полпути из кустов выскакивают гоблины")
            activate_encounter(goblins)
            return  # → обратно в main loop, active = [goblins, player]

        if npc_interruption(events):
            narrate("Тебя окликает слуга — срочные новости")
            return  # прерывание

    # Дошёл без происшествий
    move_player(destination)
    narrate(f"Спустя {total_hours}ч ты прибываешь. За время пути: {summary}")
```

Размер чанка — решение Мастера:
- Путешествие → 30 мин
- "Жду минуту" в активной сцене → 6 секунд (раунд)
- "Жду до утра" в безопасном месте → 1 час

### Длительные действия при активных НПС

Мастер решает, а не хардкод:
- "Жду час" в бою → "Сейчас не лучшее время для медитации"
- "Ухожу" при мирных НПС → Мастер деактивирует их, начинает путешествие
- Прерывание: НПС может реактивироваться если случилось что-то важное

## Area — подуровень внутри Region

Region — большая зона (Невервинтер, Лес Мечей).
Area — маленькая: комната в таверне, перекрёсток, поляна.

Все в одной area слышат друг друга. Активация НПС — по area, не по region.

Area как атрибут Entity: `area_id` внутри `region_id`. Детали реализации — позже.

## Живой мир: три уровня сознания НПС

Ключевой принцип: **каждый НПС всегда "живой". Вопрос — насколько часто
и подробно мы его будим.**

НПС не переключается между "автомат" и "живой". У него спектр:

### Уровень 1: Спящий (формулы, без LLM)

- Расписание, маршруты, базовые реакции
- "Кузнец в кузнице с 8 до 18" — автомат
- Тикает дёшево: раз в час / раз в день
- Достаточно для фоновой жизни мира

### Уровень 2: Полусознательный (дешёвый LLM, батчами)

Триггер — событие мира затронуло НПС:
- Война объявлена → разбудить лидеров, военных
- Друг погиб → разбудить близких
- Политический переворот → разбудить амбициозных
- Случайно (редко) → НПС сам инициирует действие

Один LLM-вызов, сжатый промпт:

```
Ты: Борис, кузнец, 34 года. Трейты: добрый, семьянин, никогда не воевал.
Случилось: Война с Зентилом. Деревню призвали к оружию. Друг Марек записался.

Как это на тебя повлияло? → JSON:
{
  "trait_changes": ["стал тревожным", "сомневается в короле"],
  "schedule_change": "записался в ополчение, тренируется вместо кузницы",
  "action": "прощается с женой перед уходом",
  "inner_thought": "Не хочу, но Марек уже там, не могу его бросить"
}
```

Можно батчить: группа НПС одной деревни за один вызов для связной картины.
Отдельные вызовы — для "важных" персонажей.

Результат: трейты, расписание, состояние НПС **реально обновляются**.
Когда игрок встретит его позже — LLM уровня 3 увидит актуальный контекст.

### Уровень 3: Полностью сознательный (полный контекст, tool use, 6 сек)

- Рядом с игроком или в критической сцене
- Полная история, восприятие, тактика, диалог
- Каждый раунд — отдельный LLM-вызов с tool use
- Дорого, но это и есть игра

### Механизм пробуждения

```python
class EntitiesLayer:
    def tick(self, delta, world_state):
        # 1. Формулы для всех (уровень 1)
        self._tick_schedules(delta)

        # 2. Кого разбудить до уровня 2?
        triggers = self._eval_wake_triggers(world_state)

        # 3. Полусознательный LLM-вызов для разбуженных
        self._batch_awaken(triggers)

        # 4. Применить решения — обновить трейты, расписания
        self._apply_decisions()

    # Уровень 3 (полностью сознательный) управляется
    # game_loop через take_turn(), не через tick()
```

### Пример: три месяца в пещере

Игрок ушёл на 3 месяца. За это время:

1. **Geography** тикнул ~90 раз — сезоны, погода
2. **Politics** тикнул 3 раза — началась война (формула)
3. **Settlements** тикнул 3 раза — деревня потеряла мужчин, упало благополучие
4. **Entities (уровень 1)**: расписания обновились автоматом — кузнец переведён
   в статус "ополченец"
5. **Entities (уровень 2)**: война — триггер пробуждения. LLM решает за каждого
   (батчем): кузнец стал тревожным, трактирщица прячет сбережения, староста
   пьёт от стресса
6. Игрок вернулся → кузнец активируется (уровень 3). LLM видит: "ты был на
   войне 2 месяца, потерял друга, стал замкнутым" → и играет от этого

**LLM не для симуляции в реальном времени. LLM для осмысления событий
и принятия решений, когда это важно.**

## Открытые вопросы

- **Батч vs индивидуально**: один LLM-вызов на группу НПС или по одному на
  каждого? Батч дешевле и создаёт связность, индивидуальный — точнее.
  Вероятно гибрид: батч для масс, индивидуально для ключевых.
- **Триггеры пробуждения**: какие события будят до уровня 2? Нужен конкретный
  список или система приоритетов.
- **Area**: как реализовать подуровень внутри region? Отдельный слой?
  Часть geography? Просто атрибут на entity?
- **Формат trait_changes**: свободный текст или структурированный? Свободный
  богаче, структурированный проще обрабатывать.
- **Стоимость**: сколько LLM-вызовов генерирует мотка 3 месяцев? Если 50 НПС
  и 3 триггера — 150 вызовов или 15 батчей? Нужна оценка.
