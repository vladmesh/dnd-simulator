# Консолидация rules/

Обсуждение 2026-03-20.

## Проблема

Чистые формулы сейчас разбросаны:
```
rules/dice.py                        — дайсы
rules/checks.py                      — D&D чеки
layers/geography/formulas.py         — температура, дневной свет, путешествия
layers/politics/formulas.py          — войны, торговля, стабильность
layers/settlements/formulas.py       — урожай, население, захват
```

Все эти формулы одинаковы по природе: чистые функции, без состояния, без I/O.
`harvest_modifier(weather, terrain)` ничем не отличается от `attack_roll(modifier, ac)`.

## Решение

Перенести все формулы в rules/:
```
rules/
├── dice.py           — дайсы
├── checks.py         — D&D чеки (attack roll, ability check, saving throw)
├── geography.py      — температура, дневной свет, сезоны, путешествия
├── politics.py       — войны, торговля, стабильность, дипломатия
├── settlements.py    — урожай, население, захват
└── combat.py         — (будущее) resolve атак
```

Слои (layers/) остаются ответственными за **стейт + оркестрацию**: хранят данные,
вызывают формулы из rules/, генерируют события.

## Плюсы

- Одно место для всех формул — легко найти, легко тестировать
- Переиспользование между слоями без кросс-импорта (поселениям нужна
  формула из географии → `from rules.geography import ...`)
- Чистое разделение: rules/ = как считать, layers/ = что хранить и когда вызывать

## Миграция

Инкрементальная. Переносим formulas.py → rules/{domain}.py, обновляем импорты в
слоях, тесты уже называются test_{domain}_formulas.py — не переименовываем.
