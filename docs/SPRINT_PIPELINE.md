# Sprint Pipeline

Процесс разработки одного спринта. Каждый спринт = набор связанных механик, реализованных от планирования до закрытия. Пайплайн автоматизирован через скиллы — каждый шаг имеет свою команду.

## Артефакты

```
docs/STATUS.md                 — единый файл состояния проекта (текущий спринт, история)
docs/sprints/NNN-slug/
├── sprint.md                  — цель, контекст, фазы, решения, результаты
├── tasks/                     — файлы задач (phaseN-taskM-slug.md)
└── e2e/                       — E2E отчёты по фазам (phaseN-report.md)
```

`docs/STATUS.md` — быстрый ответ на "где мы сейчас": текущий спринт, фаза, прогресс, история завершённых спринтов. Один файл на весь проект, обновляется каждым скиллом.

## Шаги

### 1. Планирование → `/new_sprint`

- Читаем roadmap, backlog, vision, предыдущий спринт.
- Сократовский диалог: предлагаем варианты скоупа с аргументами, выбираем по зависимостям.
- Нарезаем на фазы (вертикальные слайсы — все слои по чуть-чуть, не "бэк → фронт → инфра").
- Результат: `sprint.md` с целью и фазами, обновлённый `docs/STATUS.md`.

### 2. Планирование фазы → `/plan_phase`

- Читаем sprint.md, ревьюим код, нарезаем фазу на 2-4 задачи.
- TDD: каждая задача имеет секцию "Tests First" с продуктовыми тестами.
- Архитектурный чек: если фундамент плохой — стоп и отчёт, не строим на плохом.
- Результат: файлы задач в `tasks/`.

### 3. Реализация → `/implement` (цикл по задачам)

Для каждой задачи:

1. **RED** — пишем тесты (продуктовые, не низкоуровневые). Тесты падают.
2. **GREEN** — минимальная реализация чтобы тесты прошли.
3. **Verify** — `make check`. Если старые тесты упали — анализируем контракт, не слепо правим.
4. Обновляем `docs/STATUS.md`, коммит (без push).

Если видим хардкод, DRY violation, раздутые функции — стоп и отчёт. Лучше остановиться чем наращивать техдолг.

### 4. Закрытие фазы → `/close_phase`

1. Интеграционные тесты (`make test-integration`) — дописываем новые если фаза добавила функционал.
2. E2E через Playwright — новый функционал + базовый регресс. Debug mode, анализ логов.
3. Quick-fix <5 мин — сразу. Серьёзные баги — блокеры.
4. Отчёт в `e2e/phaseN-report.md`.
5. Фаза закрывается ТОЛЬКО если нет блокеров.

### 5. Аудит → `/audit` + `/audit_triage`

После всех фаз:

1. `/audit` — полное сканирование кодовой базы.
2. `/audit_triage` — сортировка находок:
   - **Quick-fix** (<5 мин, безопасно) — фиксим на месте.
   - **Sprint-relevant** (влияет на код спринта) — берём в рефакторинг-фазу.
   - **Backlog** (всё остальное) — в `docs/BACKLOG.md`.
3. Если есть sprint-relevant находки — создаём рефакторинг-фазу, реализуем, закрываем.

### 6. Финальный E2E → `/e2e`

После аудита и рефакторинга — ещё один полный E2E. Должен быть зелёный.

### 7. Закрытие спринта → `/close_sprint`

Строгий гейт. Проверяет ВСЁ:

- [ ] Все фазы закрыты
- [ ] Аудит проведён (дата после последней фазы)
- [ ] Findings аудита обработаны
- [ ] Post-audit E2E зелёный
- [ ] `make test-integration` зелёный

Если всё ок: `/update-docs`, заполняем Results, коммит и **push**. Единственный момент когда код уходит в remote.

Если хотя бы один пункт не выполнен — блокер, ничего не пушится.

## Техспринты

Раз в 4-5 спринтов — техспринт:

- Разбор бэклога целиком.
- Детальный аудит (не только текущий спринт).
- Обновление скиллов и документации.
- Пересмотр этого пайплайна.

## E2E: правила

- По дефолту без LLM (`--with-llm` если фича касалась LLM).
- Регресс по плейбуку (`docs/e2e-playbook.md`) + auto-discovery по git log.
- Запускаются после каждой фазы и после аудита.
- Quick-fix на месте, серьёзное — блокер.

## Бэклог

Всё что не входит в текущий скоуп:

- Идеи возникшие по ходу реализации.
- Баги не касающиеся скоупа напрямую.
- Техдолг найденный на аудите но не критичный.

Записывается в `docs/BACKLOG.md` с приоритетом и тегами.
