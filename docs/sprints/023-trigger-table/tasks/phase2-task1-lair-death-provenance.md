# Task: Принадлежность смерти логову

**Date:** 2026-07-13
**Sprint:** 023-trigger-table
**Phase:** 2 — Событийный write-back — смерти логова

## Description

Добавить материализованным существам явную типизированную provenance логова и переносить её в
`EntityDiedPayload`. Сейчас связь instance ID с логовом хранится только во внутренней таблице
`EntitiesLayer._materialized_lairs`, поэтому подписчик другого слоя не может отличить смерть ядра от смерти
обычного временного монстра. Provenance должна различать ядро и участника ростера, не выводиться из имени или
порядка ID и переживать сериализацию существа.

## Tests First

- Материализовать логово с ядром и миньонами через штатный `EntitiesLayer.update_activation`, убить ядро реальной
  атакой и проверить, что мировой `ENTITY_DIED` указывает ID логова, роль ядра и шаблон погибшего.
- Убить миньона из того же логова и проверить ту же принадлежность с ролью участника, без ложной отметки ядра.
- Убить обычное временное существо встречи и проверить, что событие смерти не приписывает его логову.
- Сохранить и загрузить entities state с материализованным существом логова и проверить, что последующая смерть
  сохраняет исходную provenance.

## Implementation

Ввести небольшой типизированный value object для происхождения существа логова в `core/` или эквивалентные
строгие поля на `Creature`. Заполнять его в `layers/entities/materialization.py` из `lair_id`, template ID и роли
ядра/участника. Протянуть поля через `layers/entities/save_models.py` и `entity_serialization.py`, затем добавить
необязательную provenance в `EntityDiedPayload` и заполнять её в `combat_resolution.handle_death` из погибшей
цели. Не использовать `_materialized_lairs` как источник истины при формировании события: запись может быть
восстановлена из сейва без этой эфемерной таблицы.
