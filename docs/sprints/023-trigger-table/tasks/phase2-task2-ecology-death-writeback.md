# Task: Немедленный write-back смерти в ecology

**Date:** 2026-07-13
**Sprint:** 023-trigger-table
**Phase:** 2 — Событийный write-back — смерти логова

## Description

Подписать `EcologyLayer` на типизированный `ENTITY_DIED` с provenance логова. Смерть ядра должна немедленно
переводить логово в `DEPLETED` и ставить `core_alive=False`, пока сцена ещё материализована. Смерть миньона должна
сразу удалять одну соответствующую запись из `alive_members`, чтобы значимая потеря не зависела от будущей
дематериализации. Старый `LAIR_DEMATERIALIZED` остаётся сверкой оставшегося ростера и не должен откатывать уже
записанную смерть или терминальный depletion.

## Tests First

- Провести реальную атаку по ядру материализованного логова через мировой event flow и проверить до выхода из
  локации: `core_alive=False`, `LairState.DEPLETED`, запрос `LAIRS_AT_LOCATION` больше не предлагает ядро.
- После немедленной смерти ядра сохранить мир, загрузить его без дематериализации и проверить, что логово остаётся
  depleted и больше не материализует ростер.
- Убить одного из нескольких одинаковых миньонов и проверить, что ecology уменьшает ростер ровно на один template,
  сохраняет логово активным и не теряет результат после save/load.
- Отправить смерть обычного существа, неизвестного логова и повтор того же события: чужое состояние не меняется,
  обработка идемпотентна и не падает.
- После событийного write-back дематериализовать сцену и проверить, что survivor reconciliation сохраняет
  `core_alive=False` и терминальный `DEPLETED`, а не возвращает старое состояние.

## Implementation

Добавить в `layers/ecology/lairs.py` отдельную операцию применения `EntityDiedPayload` к `dict[str, Lair]` и
вызвать её из `EcologyLayer.handle_event`. Для ядра обновлять `core_alive` и терминальный `LairState`; для участника
материализовать `alive_members` из полного ростера при первой потере и удалить одно совпадение template ID.
Повторные и устаревшие события должны быть безопасным no-op. Согласовать `apply_lair_dematerialize` с
терминальностью `DEPLETED`: дематериализация уточняет выживших и время респауна, но не оживляет ядро и не откатывает
depletion. Закрыть `lair-death-event` в `docs/BACKLOG.md` после зелёной реализации.

## Developer Notes

`EcologyLayer` применяет provenance из `EntityDiedPayload` к абстрактному ростеру сразу после смерти. Для
идемпотентности обработанные entity ID сохраняются вместе с runtime state логова. Дематериализация продолжает
сверять выживших, но не может оживить ядро или вывести логово из terminal `DEPLETED`.
